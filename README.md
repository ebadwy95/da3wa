# Da3wa — دعوات أفراح إلكتروني

نظام دعوات أفراح إلكتروني: رابط شخصي لكل ضيف، تأكيد حضور بحد أقصى للمرافقين،
QR Code للدخول يوم الفرح عبر واتساب، سكانر للباب، وتقرير لحظي للعروسين.

## التشغيل محليًا

يتطلب Node.js 20 أو أحدث.

```bash
npm install
npm run dev
```

المشروع فيه `.env.development.local` مخصّص للتطوير المحلي فقط — **بدون** بيانات
Upstash أو Wati. يعني `npm run dev` يقرأ ويكتب في `data/db.json` على جهازك، ولا
يلمس بيانات الأفراح الحقيقية ولا يرسل أي رسالة واتساب فعلية. Next يحمّل هذا
الملف قبل `.env.local`، فقيمه هي التي تسود أثناء التطوير.

لتشغيل نسخة تستخدم بيانات الإنتاج (نادرًا ما تحتاج ذلك) احذف
`.env.development.local` مؤقتًا.

للنشر: انظر `.env.example` لقائمة المتغيّرات المطلوبة كاملة.

## الصفحات

| المسار | لمن | الدخول |
|---|---|---|
| `/admin` | مسؤول المنصّة | `ADMIN_PASSWORD` |
| `/couple` | العروسين | اسم مستخدم وكلمة مرور لكل زفاف |
| `/scan` | موظف الباب | رمز مسمّى خاص بالزفاف |
| `/invite/[id]?t=token` | الضيف | توكن موقَّع داخل الرابط |

## التخزين

كل حالة التطبيق مستند JSON واحد في Upstash Redis تحت المفتاح `da3wa:db`
(`events`, `guests`, `messages`, `checkinLogs`). بدون
`UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` يقع التطبيق على ملف
`data/db.json` محلي — مناسب للتطوير فقط، وغير دائم على Vercel.

كل عملية كتابة تمرّ عبر `withDb()` في `src/lib/db.js`، وهي تستخدم
compare-and-set على عدّاد نسخة، وتعيد المحاولة تلقائيًا إذا سبقها طلب آخر. هذا
يمنع ضياع تسجيلات الدخول ليلة الفرح حين يمسح أكثر من موظف في نفس اللحظة.

> **مهم عند إضافة كود جديد:** الدالة التي تمرّرها لـ `withDb()` قد تُنفَّذ أكثر
> من مرة. لا تضع بداخلها أي شيء يجب أن يحدث مرة واحدة فقط (إرسال واتساب مثلًا) —
> اكتب الحالة أولًا، ثم نفّذ الأثر الخارجي، ثم سجّل نتيجته في استدعاء
> `withDb()` ثانٍ. انظر `src/app/api/guests/[id]/confirm/route.js` كنموذج.

## واتساب (Wati)

الإرسال الحقيقي عبر [Wati](https://wati.io) — API endpoint + access token في
`WATI_API_ENDPOINT` / `WATI_ACCESS_TOKEN`. لازم Template معتمد من Meta لإرسال
أول رسالة، واسم كل قالب في متغيّر بيئة خاص به:

- `WATI_INVITE_TEMPLATE_NAME` — رسالة الدعوة الأولى (المتغيّرات: name, couple, link)
- `WATI_QR_TEMPLATE_NAME` — رمز الدخول بعد التأكيد (المتغيّرات: name, couple)

إذا كان Wati مضبوطًا واسم القالب ناقصًا، **يرفض التطبيق الإرسال** بدل أن يستبدل
القالب بواحد افتراضي — الرسائل المُرسَلة لا يمكن استرجاعها.

## نظام التصميم

الألوان والخطوط والمسافات كلها في `src/app/globals.css` كمتغيّرات CSS، ومعروضة
لـ Tailwind عبر كتلة `@theme` (فتقدر تكتب `text-ink-2` و `border-line`
مباشرةً). لا تكتب ألوانًا خامًا (hex) داخل الصفحات.

- خط الواجهة: **Rubik** — يغطي العربية واللاتينية معًا، فالأرقام والأكواد داخل
  الجُمل العربية لا تسقط على خط آخر.
- خط العرض الاحتفالي: **Aref Ruqaa** — لأسماء العروسين والعناوين في الدعوة فقط،
  ولا يُستخدم أبدًا في لوحات التحكم.
- الأيقونات: SVG محلية في `src/components/icons.js` — لا إيموجي، لأن الإيموجي
  يرسمه نظام تشغيل الضيف فيظهر مختلفًا على كل جهاز.
- أصغر مساحة لمس `--tap` = 44px، وكل عناصر التحكم مبنية عليها.
