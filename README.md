# Da3wa — دعوات أفراح إلكتروني

نظام دعوات أفراح إلكتروني: رابط شخصي لكل ضيف، تأكيد حضور بحد أقصى للمرافقين،
QR Code للدخول يوم الفرح عبر واتساب، سكانر للباب، وتقرير لحظي للعروسين.

## التشغيل محليًا

يتطلب Node.js 20 أو أحدث.

```bash
npm install
npm run dev
```

المشروع فيه `.env.development.local` مخصّص للتطوير المحلي فقط — **بدون** بيانات
Upstash أو Wati. يعني `npm run dev` يقرأ ويكتب في `data/db.json` على جهازك، ولا
يلمس بيانات الأفراح الحقيقية ولا يرسل أي رسالة واتساب فعلية. Next يحمّل هذا
الملف قبل `.env.local`، فقيمه هي التي تسود أثناء التطوير.

لتشغيل نسخة تستخدم بيانات الإنتاج (نادرًا ما تحتاج ذلك) احذف
`.env.development.local` مؤقتًا.

للنشر: انظر `.env.example` لقائمة المتغيّرات المطلوبة كاملة.

## الصفحات

| المسار | لمن | الدخول |
|---|---|---|
| `/admin` | مسؤول المنصّة | `ADMIN_PASSWORD` |
| `/couple` | العروسين | اسم مستخدم وكلمة مرور لكل زفاف |
| `/scan` | موظف الباب | رمز مسمّى خاص بالزفاف |
| `/invite/[id]?t=token` | الضيف | توكن موقَّع داخل الرابط |

## التخزين

كل حالة التطبيق مستند JSON واحد في Upstash Redis تحت المفتاح `da3wa:db`
(`events`, `guests`, `messages`, `checkinLogs`). بدون
`UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` يقع التطبيق على ملف
`data/db.json` محلي — مناسب للتطوير فقط، وغير دائم على Vercel.

كل عملية كتابة تمرّ عبر `withDb()` في `src/lib/db.js`، وهي تستخدم
compare-and-set على عدّاد نسخة، وتعيد المحاولة تلقائيًا إذا سبقها طلب آخر. هذا
يمنع ضياع تسجيلات الدخول ليلة الفرح حين يمسح أكثر من موظف في نفس اللحظة.

> **مهم عند إضافة كود جديد:** الدالة التي تمرّرها لـ `withDb()` قد تُنفَّذ أكثر
> من مرة. لا تضع بداخلها أي شيء يجب أن يحدث مرة واحدة فقط (إرسال واتساب مثلًا) —
> اكتب الحالة أولًا، ثم نفّذ الأثر الخارجي، ثم سجّل نتيجته في استدعاء
> `withDb()` ثانٍ. انظر `src/app/api/guests/[id]/confirm/route.js` كنموذج.

## واتساب (Wati)

الإرسال الحقيقي عبر [Wati](https://wati.io) — API endpoint + access token في
`WATI_API_ENDPOINT` / `WATI_ACCESS_TOKEN`. لازم Template معتمد من Meta لإرسال
أول رسالة، واسم كل قالب في متغيّر بيئة خاص به:

- `WATI_INVITE_TEMPLATE_NAME` — رسالة الدعوة الأولى
- `WATI_QR_TEMPLATE_NAME` — رمز الدخول بعد التأكيد

### القوالب

| القالب | الحالة | المتغيّرات |
|---|---|---|
| `main_msg` | ✅ معتمد | `name`, `link` |
| `da3wa_invite_link` | ⏳ قيد المراجعة | `name`, `groom`, `bride`, `link` |
| `da3wa_qr_delivery` | ⏳ قيد المراجعة | `name`, `groom`, `bride` |
| `da3wa_event_reminder` | ⏳ قيد المراجعة — **غير مربوط بالكود** | `name`, `groom`, `bride`, `date`, `time`, `venue`, `maplink` |

`main_msg` هو الوحيد المعتمد حاليًا، ومتغيّراته (`name`, `link`) موجودة أصلًا
ضمن ما يرسله الكود — فيمكن ضبط `WATI_INVITE_TEMPLATE_NAME=main_msg` لاختبار
المسار كاملًا قبل اعتماد قوالب `da3wa_*`.

### أسماء العروسين

القوالب تطلب `{{groom}}` و `{{bride}}` منفصلين وتجمعهما بنفسها، لذلك يخزّن
سجلّ الزفاف `groomName` و `brideName` كحقلين، و`coupleNames` **مشتقّ** منهما
(`"عبدالله و نور"`) — مصدر واحد للحقيقة، ولا تخمين وقت الإرسال. المنطق كله في
`src/lib/couple.js`، وفورم الإدارة يعرض معاينة للجملة التي سيقرأها الضيف.

الأفراح المُنشأة قبل هذا الفصل تُقسَّم تلقائيًا عند أول قراءة، والنتيجة تظهر
كنصّ قابل للتعديل في فورم التعديل ليراجعها إنسان قبل أي إرسال. القسمة تتم على
واو منفصلة بمسافات فقط، فأسماء مثل «عبدالوهاب» لا تتأثر. وإن تعذّرت القسمة،
يرفض الإرسال بدل أن يصل للضيف اسم ناقص.

### التذكير التلقائي

`vercel.json` فيه cron يومي يستدعي `/api/cron/reminders`. الوظيفة تبحث عن
الأفراح النشطة التي يتبقّى عليها **يومان بالضبط**، وترسل `da3wa_event_reminder`
للضيوف الذين **أكّدوا حضورهم فقط**.

الإرسال لا يتكرّر أبدًا: كل ضيف يحمل `reminderSentAt` ويُتخطّى بعدها، فتشغيل
الوظيفة مرتين في اليوم لا يرسل لأحد مرتين. الحقل يُختَم حتى عند فشل الإرسال —
لأن فشل القالب يتكرّر يوميًا بنفس الشكل، وإعادة الإرسال لمن وصلتهم الرسالة أسوأ
من تذكير واحد ضائع؛ والفشل مسجَّل في سجلّ الرسائل لهذا السبب.

نقطة النهاية محميّة بـ `CRON_SECRET` — بدونها ترفض كل الطلبات، لأن نسخة مفتوحة
منها تعني زرّ «أرسل لكل الضيوف» متاحًا للجميع.

إذا كان Wati مضبوطًا واسم القالب ناقصًا — أو محتواه اسم افتراضي مثل
`hello_world` — **يرفض التطبيق الإرسال** بدل أن يستبدل القالب بواحد افتراضي.
الرسائل المُرسَلة لا يمكن استرجاعها. المنطق في `isUsableTemplateName()` داخل
`src/lib/wati.js`.

## افتتاحية الدعوة

كل زفاف يمكن أن يضيف فيلمه القصير وموسيقاه، فتفتح الدعوة بشاشة كاملة يضغط
عليها الضيف. الضغطة ليست زينة: المتصفحات ترفض تشغيل الصوت بدون تفاعل من
المستخدم، فالقيد نفسه تحوّل إلى لحظة فتح الدعوة.

تُخزَّن كروابط لا كملفات مرفوعة (`inviteVideoUrl`, `invitePosterUrl`,
`inviteAudioUrl`) — الفيلم يصنعه مصمّمه وله مكان أصلًا، فتبقى المنصّة خارج
مسؤولية استضافة ملفات كبيرة. أي رابط مباشر يعمل، ويفضَّل فيديو رأسي 9:16.

الفيديو والصوت عنصران منفصلان عمدًا: الفيلم يُقصّ صامتًا عادةً، والموسيقى
تُختار على حدة. الفيديو يبقى `muted` و `playsInline` (بدونها يفتحه iOS
بمشغّله الخاص ويأخذ التحكم)، والصوت يحمله عنصر `<audio>` يبقى مركّبًا بعد
انتهاء الافتتاحية حتى لا تتوقف الموسيقى، مع زر كتم دائم.

`inviteTheme` يحدّد مظهر الدعوة: `light` (كريمي وذهبي) أو `dark`. الفرق كله
في `.invite-dark` داخل `globals.css` — يعيد تعريف نفس المتغيّرات، فلا يحتاج
أي مكوّن أن يعرف أن هناك ثيمًا أصلًا. لوحات التحكم تبقى فاتحة دائمًا لأنها
أدوات عمل، لا دعوة.

## نظام التصميم

الألوان والخطوط والمسافات كلها في `src/app/globals.css` كمتغيّرات CSS، ومعروضة
لـ Tailwind عبر كتلة `@theme` (فتقدر تكتب `text-ink-2` و `border-line`
مباشرةً). لا تكتب ألوانًا خامًا (hex) داخل الصفحات.

- خط الواجهة: **Rubik** — يغطي العربية واللاتينية معًا، فالأرقام والأكواد داخل
  الجُمل العربية لا تسقط على خط آخر.
- خط العرض الاحتفالي: **Aref Ruqaa** — لأسماء العروسين والعناوين في الدعوة فقط،
  ولا يُستخدم أبدًا في لوحات التحكم.
- الأيقونات: SVG محلية في `src/components/icons.js` — لا إيموجي، لأن الإيموجي
  يرسمه نظام تشغيل الضيف فيظهر مختلفًا على كل جهاز.
- أصغر مساحة لمس `--tap` = 44px، وكل عناصر التحكم مبنية عليها.
